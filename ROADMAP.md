# blobrogue roadmap

A co-op top-down roguelike shooter (Soul Knight–inspired). Hero = the amber cowboy-blob.
Built & evolved autonomously by Ian's "personal" assistant, every few hours. Runs entirely from the box.

Live: https://blobrogue-shaoruuu.vercel.app/

## Done
- v0: playable single-player core — procedural dungeons (rooms + corridors), WASD movement, mouse twin-stick shooting, dash with i-frames, slime enemies with chase AI, HP/hearts, particles, clear-floor-then-descend loop, camera follow. Vite+TS, canvas. Deployed to Vercel.
- **Multiplayer co-op via Convex** — host/join with a 4-letter code, shared dungeon via seed+floor sync, see teammates move & shoot in real time, descend together, down-but-not-out + revive. Client uses the vanilla `ConvexClient`. Solo still works with zero Convex config (graceful degrade). See `MULTIPLAYER.md`.
- **Accounts + saved data** — lightweight persistent identity (localStorage clientId + name → Convex `players`), all-time stats (deepest floor, kills, coins, runs) that persist across sessions and show on the title + stats screens.
- **Enemy variety + boss** — bats (fast, erratic), skeletons (tanky melee), ghosts (phase through walls, semi-transparent), and a slime-king boss every 5th floor (2× size, contact damage, spawns minions, gates the exit). Deterministic seeded spawns; gentler early floors.
- **Weapons & pickups** — 12 weapons with distinct feel, gun pickups that swap your weapon, heart (heal) + coin (currency) drops. Current weapon in the HUD. The originals (pistol / shotgun / rapid) plus 6: **Hornet** SMG (fast, light spray), **Thunderbolt** hand cannon (slow, huge slug, self-knockback), **Triplet** burst (3-pellet spatial fan), **Rebound** ricochet (bounces off walls), **Wisp** homing (curves to the nearest enemy), and **Tesla** (chains lightning between enemies), plus 3 more: **Boomstick** sawn-off (8-pellet point-blank devastator with a big self-shove), **Longshot** railgun (near-hitscan precision slug; pierce only via the Full Metal item), and **Nailer** (fast full-auto that ricochets once, reusing the existing `bounce` field). Each has its own full feel profile (SFX + trauma/recoil/kick/knockback). The behavior weapons add one optional per-bullet field each (`bounce` / `homing` / `chain`+`chainRange`), so they auto-synergize with the item system and leave the originals byte-for-byte unchanged.
- **Minimap + stats HUD** — top-right minimap (rooms/corridors, player, exit, enemy & teammate dots), a clean hearts/floor/kills/coins/weapon bar, and a hold-Tab run/all-time stats panel. Dark-navy + amber aesthetic, layout-shift-free.
- **Juice / procedural animation** — every character and pickup is animated: idle bob + squash-and-stretch, moving hop + lean, shoot recoil + muzzle flash, hit flash, death pop/squash/fade, spinning coins, boss breathing + spawn telegraph. Plus optional drop-in frame spritesheets (horizontal strips) with procedural fallback. See `ART.md`.
- **In-run item / synergy system** — clear a floor, descend, and pick one of three randomly-drawn **blessings** (à la Isaac / Nuclear Throne trinkets). 16 curated items feed a data-driven `PlayerMods` struct (`src/game/items.ts`) that the fire / move / dash / damage paths read, so picks stack and compound into distinct builds — Split Shot + Scattergun pellet walls, Glass Cannon / Big Iron / Deadeye burst, Adrenaline + Berserk low-HP frenzies, Vampire Fang / Thorns / Second Wind / Coin Magnet utility. A pixel-art "CHOOSE A BLESSING" overlay (`src/ui/blessing.ts`, keyboard 1/2/3 + arrows/Enter or click) pauses between floors; collected blessings show as a HUD glyph strip and in the hold-Tab RUN STATS panel. Solo-authoritative; co-op picks are per-client and purely local (non-networked, non-breaking).
- **Enemy pathfinding (flow field)** — ground chasers (slime, bat, skeleton) now route *around* walls instead of walking straight into them and sliding uselessly. A shared BFS flow field (`src/game/pathfind.ts`, Dijkstra map) floods walkable tiles from every living player each ~0.2s (or on the local player's tile change) and each enemy follows the downhill gradient; with clear line of sight it beelines for a crisp melee approach. Bats keep their erratic wobble layered on top, the slime pulses a hop-cadence toward you (squash-synced, balance-neutral), and an anti-stuck net nudges anything wedged on geometry. Local/AI-only — co-op stays desync-free (enemies are already per-client). Allocation-conscious: typed arrays reused, BFS throttled, zero per-enemy-per-frame allocations.
- **Item icons + "YOUR BUILD" panel + held weapon on the blob** — the in-run blessings now read as real 48px icon sprites (`public/sprites/item_<id>.png`) on the "CHOOSE A BLESSING" pick cards and in the HUD, replacing the single-letter glyphs. The cryptic top-left glyph strip is now a labeled **YOUR BUILD** panel: rarity-framed icon chips with duplicate stacking (`xN`) and hover tooltips (name + one-line desc), plus the desc line added to the hold-Tab stats list. The equipped gun is drawn over the hero, centered at the muzzle-flash anchor and rotated to aim (`held_<id>.png`, with a left-aim vertical flip and a small recoil nudge on fire); local + co-op players both show it. Everything degrades gracefully, mirroring the `SHEETS` sprite pattern: icons fall back to their letter glyph and the held overlay falls back to the pistol / draws nothing when the sprite isn't loaded, and the held-weapon registry is opt-in so only listed weapons are ever fetched. **Art note:** the icon/held PNGs are not yet committed to `public/sprites/`, so today the wiring renders its glyph/no-overlay fallback (with transient image 404s) and lights up automatically the moment the art lands — no code changes needed. Held sprites are specced only for pistol/shotgun/rapid, so the six newer guns (smg/cannon/burst/ricochet/homing/tesla) reuse the pistol overlay for now.
- **Game-feel & sound pass** — a sample-based WebAudio engine (`src/game/audio.ts`) now plays **real generated audio** shipped in `public/audio/`: per-weapon shots (all 9 weapons have their own sound), enemy attack/hit/death, hurt, dash, pickups, descend, boss roar, game-over, plus full-length looping **instrumental dungeon/boss tracks** (crossfaded on swap). Combat sounds ship 3 variants each and every one-shot picks a random variant + a ±5% pitch jitter so rapid fire never sounds like one clip on repeat; decoded buffers are cached, common sounds preload on the first gesture, and any file that fails to load falls back to the original procedural synth so a missing asset can never break the game. **Hit-stop** on kills/heavy hits; **trauma-based screen shake** (per-event, intensity slider); **death gibs + impact particles** (wall sparks vs enemy puffs), floor decals, directional muzzle flash, shell casings; per-weapon feel (recoil + camera kick + shake + shotgun knockback); a run-summary screen with count-up numbers; and a mute + shake settings affordance (menu + Esc pause), persisted. Solo-safe and co-op-gated (far-off events don't spam audio/juice).

- **Interactable world: destructible props + treasure chests** — rooms are no longer empty boxes. Each floor now seeds a scatter of **destructible props** (`Prop` struct in `types.ts`, ~2-5 per room via a seeded `Rng` with the same salt+prime placement pattern as weapon pickups/torches, so co-op clients agree on the layout; spawn point + exit tile kept clear): **crates** (hp 4 → gibs + 60% coin / 15% heart), **pots** (one-shot → shatter puff + 35% coin, cheap tactile juice), **barrels** (hp 3 → gibs + maybe a coin), **explosive barrels** (hp 3 → an AoE that reuses the boss shockwave shape: ~6 damage to every enemy AND prop within ~70px so they **chain-detonate** each other, big trauma+freeze, orange gib/spark burst, and self-damage that respects the player's i-frames — the environment becomes a weapon), and non-destructible **braziers** (atmosphere + a warm light source, drawn as the static base with the shared animated torch flame + additive glow layered on top). Props take damage in the friendly-bullet loop right after the enemy checks (flash + puff, bullet consumed unless it pierces) on the shared floor state exactly like enemies, and a **dash** smashes straight through them (the dash i-frames make popping an explosive barrel this way a clean risk/reward). Break art is 3-frame 192×64 strips (frame 0 = intact) played once (~0.25s) then removed; hot paths are allocation-free (idle bob/flash via the shared xform scratch, array compaction only on the frame a break finishes). **Treasure chests** (`Chest` struct) are **touch-to-open** (mirrors the coin/heart pickup model — no new input): walk over one and it plays its 3-frame open clip and rolls a reward ONCE — wood chests (placed in 1-2 non-spawn/non-exit rooms) give 55% a 3-6 coin cache, 20% a heart, 18% a **blessing** pick (`offerBlessing()`, the "chest → power-up" moment), 7% a random weapon; the **boss chest** is spawned where the boss dies (replacing the old flat heart+coin drop) and guarantees a blessing plus the heart + coin cache. Co-op determinism: placement is seeded (shared), destruction resolves via bullets/explosions on shared floor state, and blessing chests offer **each client its own pick** (never a shared blessing) while coins/hearts/weapons stay first-come world pickups — no new networking, purely additive to combat/pickups. All art (`crate_break`/`pot_break`/`barrel_break`/`barrel_explosive_break`/`barrel_explosive`/`brazier`/`chest_open`) is committed under `public/sprites/`, and the `barrel`/`chest` SFX clips are wired into the audio map.

- **Dev sandbox / "creative mode" page (`?dev=1`) + sprite/anim viewer (`?dev=sprites`)** — a hidden studio debug tool for testing game feel fast, gated entirely behind a query flag (never linked from the menu, so a normal player can't stumble in) and dynamically imported so the whole dev layer tree-shakes out of the normal play bundle. `?dev=1` boots the **real `Game`** into a single large walled **arena** (reuses the exact `Dungeon`/`Room` shape, so movement/shooting/AI/pathfinding all run unchanged) with a pixel-font DOM **DEV PANEL** (styled against the canonical `:root` tokens — Silkscreen `--f-ui` / VT323 `--f-num`, dungeon purple + amber): a button per enemy kind with **×1/×5/×10** bulk spawn (slime/bat/skeleton/ghost/spitter/boss) + **clear all**, a spawn-at-cursor toggle, all **9 weapons**, every **blessing** (grant directly or pop the real chooser), **god mode** / heal / ±max-HP, **floor jump** (incl. boss floor), **prop + chest** spawns (crate/pot/barrel/explosive/brazier), a **flow-field pathfinding overlay** (downhill arrows toward the player), and a live **FPS / enemy / bullet / particle** readout. Everything routes through a small set of clearly-marked **dev-only hooks** on `Game` (`devStartSandbox`, `devSpawnEnemies`, `devClearEnemies`, `devGiveWeapon`, `devGrantItem`, `devOfferBlessing`, `devToggleGod`, `devHealFull`, `devAddMaxHp`, `devSetFloor`, `devSpawnProp`, `devSpawnChest`, `devToggleFlowDebug`, `devSnapshot`) reusing the real enemy factory, weapons, items and prop/chest spawns — so it's a faithful test of feel, not a mock. The guarded flags (`isSandbox`/`isGodMode`/`isFlowDebug`) are each one cheap branch on a hot path and always false in a real run. `?dev=sprites` is a **sprite + animation viewer**: it lists every registered sprite/spritesheet, plays each walk/death sheet frame-by-frame at its real fps with a live frame counter (slicing frames identically to the renderer — `fw = naturalHeight`), and an **Audit frames** button that visually flags degenerate frames (empty, or a skinny bbox outlier) — the in-browser mirror of `tools/audit-sprites.py`, i.e. exactly where the "skinny slime frame" bug would jump out. See `tools/README.md`.
- **Sprite-based bullet FX + enemy death animations + reworded "descend" copy** — bullets are no longer flat circles: each weapon draws a layered, additive sprite recipe (`smoke → glow → velocity-aligned trail/comet → hot core/slug`) using tintable white FX primitives in `public/sprites/fx/` (glow_round, core_dot, trail_streak, slug, spark, comet_trail, crackle, arc_chain, smoke_puff — all pure-white, intensity-in-alpha so a single `source-in` fill recolors them to the weapon tint). Tinted canvases are cached per `asset+color` (allocation-free hot path) and composite with `globalCompositeOperation='lighter'`. Per-weapon: pistol/rapid/smg/burst get streak trails (length scales with bullet speed) + core, shotgun/cannon fire glowing slugs, cannon trails smoke, homing draws a comet, tesla crackles at the core and its chain-lightning now renders a stretched `arc_chain` bolt point-to-point between enemies, and ricochet pops a `spark` flash on every wall bounce. The muzzle flash is tinted to the weapon color. Bullets carry a tiny `fx` weapon tag set at spawn; any FX sprite that hasn't loaded falls back to the original circle so a bullet always renders. **Enemy deaths** now play one-shot death spritesheets (`slime/skeleton/bat_death.png` 5-frame 320×64, `boss_death.png` 8-frame 768×96, registered as a new `death` clip in `SHEETS` at 12fps) over the existing corpse — squash-to-ground + white damage-flash + alpha dissolve, with the boss's frames 2–3 an intentional full-white VFX. Gib particles + splat decals still layer on top; the boss death runs ~0.65s, others ~0.4s (per-corpse duration). Ghost/spitter keep the procedural fade, and any missing death sheet falls back to it. Copy: the menu's offline solo button reads **▾ PLAY**, the co-op host button **▾ START RUN**, the between-floor banner now says **DOWN TO FLOOR N**, and a pulsing **▾ GO DOWN** prompt floats over the exit portal once a floor is cleared. All FX/death art is committed and reproducible via `tools/gen-fx.py` + `tools/gen-death.py`.

- **Smooth co-op movement (entity interpolation) + distinct player colors** — remote teammates no longer jitter. Convex presence rows still arrive as discrete snapshots, but the renderer no longer draws them at the raw latest coords; a small per-player interpolation buffer (`src/net/interp.ts`) keeps the last few network samples stamped with local receive time and, on every read, returns the pose at a **render clock that trails real time by one sync interval (~120ms)** — the classic client-side entity-interpolation trade: spend a fixed sliver of latency to buy motion that stays smooth through network jitter. `remotePlayers()` returns the interpolated x/y + angle-lerped aim; stale/late updates extrapolate briefly then hold, and a big jump (floor descend / respawn) snaps instead of sliding. The local player's `presence.update` push cadence went from a flat ~11Hz to **~18Hz while moving/aiming/acting** with a **1Hz idle keepalive** (only pushes on meaningful change), so the interpolation buffer stays well-fed without spamming Convex. **Colors:** the hero tint was recoloring every teammate by laying a flat 50% color over the strongly-amber base, which muddied all six palette hues toward the same amber-grey tone (they read as "all blue-ish"); `Sprites.tintedHero` now strips the amber to grayscale then **multiplies** the player color through it, so the sprite's shading survives but the hue reads as a vivid, unambiguous amber/cyan/green/pink/violet/orange (verified all six distinct, masked back to the silhouette). Name labels, minimap dots, and shot tracers already used `playerColor()`, so they now match the body. Solo play is untouched (all of this is behind the co-op path); descend-sync, revive, and shot tracers are unchanged. `npm run build` (tsc strict) clean.
- **Elemental status effects (burn / chill / shock) + Flamethrower + elemental blessings** — the "deeper mechanics" tentpole that makes weapons, items, and props all interact. Every enemy carries local status scratch (`burn`/`burnDmg`/`chill`/`shock`/`statusTick` on the `Enemy` struct, init in `createEnemy`), ticked in `updateEnemies` — the same bullet-driven, per-client model as damage/knockback, so co-op stays desync-free with no new networking. **BURN** is a DoT (ticks every 0.25s, spawns ember puffs, refreshes duration + stacks `burnDmg` up to a cap); **CHILL** halves movement at the single locomotion chokepoint (`moveEnemyBy`, so every AI path + knockback respects it) and at high stacks **freezes the enemy solid** (rooted, +50% "shatter" damage) — capped/excluded on the boss so it can never be trivially locked; **SHOCK** amps damage +25% and, when the shocked enemy is hit, arcs a small zap to a nearby enemy (reuses the tesla arc core, refactored into a shared `arcLightning`). Damage amps apply once, in order (`b.damage × shock(1.25) × frozen(1.5)`), then the round's status, then the arc. Statuses reach enemies three ways: **weapons** (`burn`/`chill`/`shock` optional fields on `Weapon`/`ShotSpec`/`Bullet`, stamped exactly like `bounce`/`homing`), **items** (`burnChance`/`chillChance`/`shockChance` on `PlayerMods`, rolled at hit time so ANY weapon can go elemental — 4 new blessings: **Incendiary Rounds**, **Cryo Coating**, **Static Charge**, and rare **Elementalist** that rolls all three), and the **environment** (explosive barrels lace their blast with burn). The **Flamethrower** ("Dragon", weapon #13) fires fast tiny short-life wide puffs — a continuous flame cone with low per-hit damage that stamps burn on every round; it gets its own full feel profile across all six tables and a layered flame-stream bullet FX (warm glow + hot core + optional `flame_puff` mask). Status overlays layer on enemies via the existing `fxTinted`/`fxLayer` additive path (orange ember glow, blue frost, ice-crust `freeze_shell` when frozen, cyan crackle) + ember particles, all with graceful fallback to the always-loaded `glow_round`/`crackle` until the AD's dedicated `ember`/`frost`/`freeze_shell`/`flame_puff` masks land. Hot paths stay allocation-free (a few ops per enemy/frame; particles only spawn on burn ticks). Tuned a touch generous per the game's vibe; enemies are never nerfed. `npm run build` (tsc strict) clean.
- **Combo / kill-chain multiplier** — aggressive, continuous play now compounds. Each enemy kill bumps a **local combo counter** and refreshes a **3s window** (`COMBO_WINDOW`, tunable); let it lapse and the chain resets to 0. The combo tier drives a **coin/score multiplier** — **x1** (combo 0-4) → **x1.5** (5-9) → **x2** (10-19) → **x3** (20+) — and coins **dropped by kills** carry that multiplier baked in at drop time (props/chests stay face value; the value rides on an optional `Pickup.value`, mirroring the other opt-in per-pickup fields). A top-center **HUD widget** (`src/game/hud.ts`, canonical Silkscreen/VT323 tokens) shows the big tier-tinted multiplier over `N COMBO` + a **drain bar**: the mult **punches/scales** when the chain ticks up, the bar tracks the window and **flashes** as it's about to expire, and the whole thing fades in/out on transform+opacity only (zero layout shift), resetting visibly when the chain drops. **Feel** reuses the existing juice systems — the kill sound **rises in pitch** with the chain (boss keeps its deep roar) and kill-**trauma ramps** with the tier so a hot streak kicks harder. Strictly **per-local-player** like `kills`/`coins` — never published or networked, so co-op stays desync-free — and it works in the `?dev=1` sandbox for free (real `killEnemy` path). `npm run build` (tsc strict) clean. The HUD widget now renders the AD's authored art — the `combo_badge` stamped-plate frame behind the live `xN` text, a one-shot `combo_burst` flare on each tier-up, and the `combo_meter` frame+fill drain bar — all tinted per-tier via CSS `mask-image` (the DOM equivalent of the `fxTinted` white-mask trick, so the tier color is code-owned).
- **Clarity + legibility pass** — a "make the systems read" sweep, no new art. **(1) Two-shaded-side wall depth (Soul Knight extruded-block look):** `renderTiles()`'s wall pass keeps the lit `wall_top` cap + the dark `wall_face` front (where the tile below is floor) but now also paints mid-dark **side faces** on exposed left/right edges — precomputed inward-fading gradients (`WALL_SIDE_*`, built once in the ctor, zero per-frame allocation) — plus an extra **corner darken** where a side meets the front, so walls read as 3D cubes instead of flat caps. Tones step cap `#2f2350` → front `#241a3a` → side `~#1b1530`; swap-ready for `wall_face_left/right.png` if the art director ever drops them. **(2) Dash onboarding + label:** the bottom-left dash meter now shows the input as a `SHIFT` keycap next to the `DASH` label, turns **green with a full-chip outline when ready** (vs blue while cooling) so "I can dash now" is unmissable, and a subtle, auto-dismissing **controls hint** ("WASD MOVE · MOUSE AIM · CLICK SHOOT · SHIFT DASH") fades in for ~5s on the **first run ever** (persisted via `settings.controlsHintSeen`, opacity-only so it never shifts layout — never nags again). **(3) Guaranteed spawn visibility:** `placeChests()` now guarantees **at least one wood chest on every floor including floor 1** (scans non-spawn rooms for a free floor tile if every seeded roll lands on the spawn/exit tile, never blocks the portal), props bumped to **3-6 per room** so rooms read as furnished, and weapon pickups are more generous early (guaranteed from floor 2, a good chance of a second from floor 3) so the other 8 weapons get discovered. All still seeded (co-op-deterministic) — only rates/guarantees changed, not the RNG pattern. **(4) Crosshair reticle:** the bare aim ring became a proper crosshair — ring + four tick marks + center dot. `npm run build` (tsc strict) clean.

## Systems-depth vision (game designer, DECIDED) — "persistent base, ephemeral expeditions"
One game shape: top-down survival-crafting-combat where our roguelike combat IS the expedition layer. Craft/gear at a persistent growing HOME BASE (Convex doc state, co-op shared) → launch instanced procedural EXPEDITIONS (the combat) → beat biome boss → unlock next tier + resources → craft better → deeper. Comps: Core Keeper, Valheim, Deep Rock.
KEY ARCHITECTURE: persist the BASE not the WORLD (Convex's strength; avoids per-tile terrain sync). Expeditions instanced/ephemeral; Quick Play still works.
Two item layers: persistent EQUIPMENT (craft/keep/bring in) vs in-run ITEMS (ephemeral build variety, lost on death) — resolves the roguelike-vs-survival tension, no rework to items spec.
QUEUE UNCHANGED: juice → combat → items/meta (all substrate the systems extend; loadouts = persistent mods, hub = Amber rendered physical).
v1 (deep+open feeling, ~20% effort, all reskins/extensions): 1) tiered biome progression (boss gates tier) 2) contiguous biomes replace floor cards 3) persistent growing hub (Amber→buildings/NPCs) 4) multi-slot equipment loadouts.
v2 (after v1 ships): gathering + SHALLOW crafting (hub stations functional) · persistent shared co-op base · base-defense wave mode (reuses combat).
v3 (if metrics justify): constrained base building (NOT freeform voxel) · day/night+hazards · deeper crafting/biomes.
HARD CUTS (refuse — the multi-year traps): freeform destructible terrain (never), persistent shared overworld (use base+instanced instead), hunger/thirst/temp meters (tedium), Minecraft-scale crafting trees (keep shallow).
DISCIPLINE: every phase independently shippable+fun; ship v1 to players BEFORE layering systems.
RELEASE MODEL PIVOT: Early Access + public roadmap (fits systems-deep games grown in public — Valheim/Core Keeper/Terraria did exactly this; turns "not fully built" into the pitch; strong wishlist+retention driver). Web demo + instant co-op = top of funnel.
